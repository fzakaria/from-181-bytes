Every byte you have to trust, explained. On i686-linux, nixpkgs builds its C compilers from source, all the way up to GCC 16.2.0, and the only program in the chain it does not build is the one below: 181 bytes of machine code that turn hexadecimal text into bytes. Point at a byte to see the line of commented source it came from.

Which nixpkgs grows from this

      

        At the nixpkgs revision this page describes, the standard environment on
        x86_64-linux and i686-linux starts from this
        chain:
        pkgs/stdenv/linux/stage0.nix
        takes the last GCC and glibc below as its first compiler and C library,
        and
        hello's derivation closure contains the hex0 seed on both
        systems. That landed with
        nixpkgs#479322
        in January 2026. Every other Linux platform still starts from a prebuilt
        bootstrap-tools tarball; on aarch64-linux, hello depends on
        bootstrap-tools.tar.xz and no seed.
      

      

        181 bytes is the binary you trust. You still trust the kernel that runs
        it, the Nix daemon that sandboxes each step, and the hardware. The rest
        is source text, which you can read.
        builder-hex0 and
        live-bootstrap
        take the kernel out of that list too.
